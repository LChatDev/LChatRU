# Настройка голосовых и видеозвонков

LChat использует WebRTC. PHP и MySQL передают сигнализацию; при возможности участники обмениваются зашифрованными медиа напрямую. Если прямое соединение невозможно, TURN передаёт трафик через себя. Сам PHP-сайт TURN-сервером не является. В групповом звонке каждый соединяется с каждым, поэтому начните с лимита 6–8 участников.

## Перед началом

1. Настройте сайт по [HOSTING.md](https://github.com/LChatDev/LChatRU/blob/main/HOSTING.md), включая доверенный HTTPS-сертификат. Разрешите браузеру микрофон и камеру.
2. Проверьте звонок с двух разных аккаунтов в разных сетях. Иногда хватает STUN; если соединение или звук не работают, настройте TURN.
3. Для TURN нужен VPS или сервис с доступными портом подключения **и диапазоном relay-портов**. Обычный PHP-хостинг обычно не запускает постоянный TURN-процесс. Одного TCP-туннеля к порту подключения недостаточно: проверьте поддержку UDP и диапазона портов. Варианты туннелей — в [TUNNELS.md](https://github.com/LChatDev/LChatRU/blob/main/TUNNELS.md).

## Пример: coturn на Linux VPS

Пример рассчитан на Ubuntu/Debian с публичным IPv4. Замените примеры своими значениями и сохраните рабочий доступ по SSH. Подробности — в [конфигурации coturn](https://github.com/coturn/coturn/blob/master/docker/coturn/turnserver.conf).

1. Направьте `turn.example.com` на публичный IPv4 сервера и установите coturn:

   ```sh
   sudo apt update
   sudo apt install coturn
   ```

2. Создайте длинный секрет, например `openssl rand -hex 32`, и храните его закрыто. Измените `/etc/turnserver.conf`:

   ```ini
   listening-port=3478
   fingerprint
   use-auth-secret
   static-auth-secret=REPLACE_WITH_YOUR_RANDOM_SECRET
   realm=turn.example.com
   min-port=49160
   max-port=49200
   no-cli
   no-tls
   no-dtls
   ```

   Здесь используется обычный TURN по UDP или TCP без TLS-порта; медиа WebRTC шифруется отдельно. Для TURN через TLS (`turns:`) настройте сертификат, ключ и TLS-порт coturn и используйте соответствующий адрес. За NAT coturn должен сообщать клиентам правильный публичный IP: настройте `external-ip` по документации coturn и пробросьте порты подключения и relay один к одному.

3. Разрешите **UDP и TCP 3478** и **UDP 49160–49200** в брандмауэре хостинга и ОС. Диапазон можно изменить, но он должен совпадать с конфигом. Запустите службу:

   ```sh
   sudo systemctl enable --now coturn
   sudo systemctl status coturn
   sudo journalctl -u coturn -n 100 --no-pager
   ```

   Название и включение службы зависят от дистрибутива. Запущенная служба сама по себе не подтверждает доступность relay-портов извне.

## Подключение LChat

В закрытом `config.php` укажите тот же секрет и свой адрес:

```php
'ice_servers' => [
    ['urls' => 'stun:stun.l.google.com:19302'],
],
'turn' => [
    'urls' => 'turn:turn.example.com:3478?transport=udp',
    'secret' => 'REPLACE_WITH_YOUR_RANDOM_SECRET',
    'ttl' => 3600,
],
'call_transport' => 'all',
'max_call_participants' => 8,
```

LChat создаёт временные учётные данные из общего секрета: в coturn используйте `use-auth-secret` и тот же `static-auth-secret`, а не отдельный фиксированный логин и пароль. Не публикуйте секрет. Если UDP до порта подключения блокируется, при включённом TCP можно использовать `turn:turn.example.com:3478?transport=tcp`; UDP relay-порты всё равно нужны. В PHP-конфиге допустим массив адресов TURN; админка показывает и сохраняет один.

Владелец также может указать URL, секрет, срок действия, лимит и маршрут звонков в `admin.php`. Пустое поле секрета сохраняет прежний секрет. Значения из базы имеют приоритет над конфигом; при необходимости удалите их кнопкой сброса. `all` разрешает прямое соединение и TURN; `relay` требует работающий TURN и направляет звонок через него.

## Проверка

1. Войдите с двух устройств в разных сетях, разрешите микрофон, начните звонок и проверьте звук в обе стороны и видео. Затем проверьте группу.
2. Для проверки TURN временно включите в админке режим только TURN и начните новый звонок. Если он работает, тест прошёл через relay. Затем верните режим прямого соединения и TURN, если не нужен постоянный relay.
3. При ошибке проверьте DNS, адрес, журнал coturn, одинаковый секрет, брандмауэр порта подключения и UDP-диапазона, внешний IP и доступность выбранного протокола. При истечении временных данных повторно войдите в звонок.
4. В Chromium `chrome://webrtc-internals` показывает типы ICE-кандидатов и состояние соединения. Успешный `relay` — полезный признак, но звук тоже нужно проверить.

На Android разрешите микрофон и уведомления. Приложение опрашивает сервер в фоне; энергосбережение может задерживать уведомления. Ограничения описаны в [ANDROID.md](https://github.com/LChatDev/LChatRU/blob/main/ANDROID.md). Дополнительно: [WebRTC и ICE](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Connectivity), [доступ к микрофону](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
