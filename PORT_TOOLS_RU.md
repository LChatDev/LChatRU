# Как управлять бесплатными туннелями

Туннель делает локальный сервис доступным снаружи через провайдера; он не обязательно открывает порт на роутере. Сначала запустите сайт и убедитесь, что на серверном ПК открывается `http://127.0.0.1:8365/`. База MySQL должна работать отдельно. Примеры рассчитаны на Windows; порт `8365` замените своим.

Публичный сайт нужно открывать по HTTPS, чтобы браузер разрешил микрофон. Туннели сайта ниже не предоставляют автоматически TURN: для TURN отдельно нужны публичный порт подключения и диапазон UDP relay-портов. Инструкция по TURN — [CALLS.md](https://github.com/LChatDev/LChatRU/blob/main/CALLS.md). Условия бесплатных тарифов и интерфейс провайдеров могут меняться; эти инструкции не проверены на всех сервисах.

## Cloudflare Tunnel: сайт со своим доменом

1. Создайте аккаунт Cloudflare, добавьте домен и настройте DNS у регистратора по указаниям Cloudflare. Для постоянного публичного имени домен должен быть в Cloudflare. Проверьте работу локального сайта.
2. В панели откройте **Networking → Tunnels → Create Tunnel**, создайте туннель `cloudflared`, выберите Windows и установите агент командой, показанной панелью. Не публикуйте токен из этой команды.
3. В маршруте укажите поддомен, например `chat`, домен и локальный сервис `HTTP` с адресом `http://127.0.0.1:8365`. Сохраните и убедитесь, что агент подключён.
4. Откройте назначенный HTTPS-адрес и проверьте вход. В `config.php` укажите этот адрес в `public_url`.
5. В панели можно изменить маршрут или удалить туннель. Для остановки работающего процесса нажмите `Ctrl+C`, а если агент установлен как служба — управляйте службой Windows. Остановка службы прерывает все её маршруты.

[Документация Cloudflare](https://developers.cloudflare.com/tunnel/get-started/). Для временных тестов существуют [Quick Tunnels](https://developers.cloudflare.com/tunnel/setup/); их адрес может измениться.

## Tailscale Funnel: публичный HTTPS без своего домена

1. Установите [Tailscale](https://tailscale.com/download), войдите на ПК-сервере и включите MagicDNS, HTTPS и Funnel в настройках аккаунта по инструкции сервиса.
2. Откройте командную строку **от администратора** и выполните:

   ```cmd
   tailscale funnel 8365
   ```

3. Подтвердите включение, если появится ссылка, и откройте полученный `https://…ts.net` с другого устройства. Посетителям Tailscale не нужен.
4. Для просмотра состояния выполните `tailscale funnel status`; для отключения текущей публикации — `tailscale funnel off`. Если команда запущена на переднем плане, её также можно завершить через `Ctrl+C`.

Funnel использует имена `*.ts.net`, разрешённые публичные TLS-порты и ограничения скорости. Обычный Tailscale Serve предназначен для частной сети и обычно требует клиент у участников. [Документация Funnel](https://tailscale.com/docs/features/tailscale-funnel).

## LocalTunnel: временный адрес для проверки

1. Установите [Node.js](https://nodejs.org/) на ПК-сервер.
2. В командной строке выполните `npx localtunnel --port 8365` и дождитесь ссылки.
3. Откройте ссылку на другом устройстве. Оставьте окно и локальный сайт работающими; для остановки нажмите `Ctrl+C`.

Адрес и доступность могут меняться, а промежуточная страница может мешать приложению или API. Это вариант для тестов, а не постоянного сервиса. [LocalTunnel](https://github.com/localtunnel/localtunnel).

## Playit.gg: управление туннелями

1. Установите агент [Playit](https://playit.gg/) на серверный ПК, запустите и привяжите его к аккаунту через предложенную ссылку.
2. В панели создайте туннель, выберите доступный протокол и укажите локальный IP `127.0.0.1` и порт нужной службы. Проверьте назначенный внешний адрес и порт в свойствах туннеля.
3. Туннель можно отключить или удалить в панели; для остановки всего агента закройте его процесс. Служба на локальном порту должна оставаться запущенной.

Проверяйте актуальные тарифы: [документация Playit](https://playit.gg/support/playit-scpsl-server/) указывает, что TCP требует Premium. Доступность UDP и диапазонов необходимо проверить в своём аккаунте; одного туннеля недостаточно для полного набора TURN relay-портов.

## LocaltoNet и ngrok

**[LocaltoNet](https://www.localtonet.com/):** создайте аккаунт, установите и запустите агент по инструкции панели, создайте HTTP/TCP/UDP-туннель с локальным адресом `127.0.0.1` и портом службы. В панели проверяйте внешний адрес, статус и управляйте туннелем; для полной остановки завершите агент. Бесплатный тариф указывает один туннель — проверьте текущие условия и поддержку необходимых портов.

**[ngrok](https://ngrok.com/):** установите агент и подключите его к аккаунту по инструкции сервиса. Для сайта выполните `ngrok http 8365`, откройте HTTPS-ссылку из окна агента; `Ctrl+C` завершает публикацию. Бесплатный тариф имеет лимиты, а для TCP нужна [проверка банковской карты](https://ngrok.com/faq). Не публикуйте токен агента. Ссылка сайта не заменяет TURN relay.

Другие программы и ограничения — в [TUNNELS.md](https://github.com/LChatDev/LChatRU/blob/main/TUNNELS.md). Не открывайте MySQL-порт в интернет для этой схемы: приложению достаточно локального соединения с базой.
