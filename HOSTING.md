# Размещение LChat на PHP и MySQL

В этой инструкции используется Apache и панель хостинга, например REG.RU. PHP обрабатывает сайт и сигнализацию звонков, MySQL/MariaDB хранит пользователей и сообщения. Для звонков нужен HTTPS, а для многих сетей — отдельный [TURN-сервер](CALLS.md). Вариант с бесплатной виртуальной машиной описан в [FREE_HOSTING.md](FREE_HOSTING.md).

## 1. Домен и хостинг

1. Направьте домен или поддомен на хостинг по DNS-данным провайдера и добавьте его в панели хостинга. Дождитесь обновления DNS.
2. Включите PHP 8.2 или новее и расширения `pdo_mysql`, `mbstring`, `fileinfo`, `curl`, `gd`. Apache должен применять `.htaccess` и `mod_rewrite`.
3. Выпустите сертификат в панели хостинга. Проверьте, что `https://ваш-домен/` открывается без предупреждений. На обычном удалённом HTTP-сайте браузер не даст доступ к микрофону.
4. Создайте в панели базу MySQL/MariaDB и пользователя с правами на неё. Запишите хост, порт, имя базы, логин и пароль. Хост базы сообщает провайдер; он может отличаться от домена сайта. Стандартный порт MySQL — `3306`.

## 2. Загрузка и конфиг

Загрузите веб-файлы в корневую папку сайта так, чтобы `index.php`, `api.php`, `app.php`, `admin.php`, `apis/`, `assets/`, `data/` и `files/` находились в ней. Сохраните скрытые файлы `.htaccess`. Исходники Android, тесты и Markdown-файлы не обязательны для работы сайта. Не загружайте чужой `config.php`, ключи подписи, `.git` или чужие данные.

Скопируйте `config.example.php` в `config.php` на сервере и замените примеры своими данными. При обновлении сохраняйте свой рабочий `config.php`.

```php
'database' => [
    'dsn' => 'mysql:host=YOUR_DB_HOST;port=3306;dbname=YOUR_DATABASE;charset=utf8mb4',
    'username' => 'YOUR_DATABASE_USER',
    'password' => 'YOUR_DATABASE_PASSWORD',
],
'install_key' => 'A_LONG_RANDOM_SECRET_AT_LEAST_32_CHARACTERS',
'site_name' => 'Мой мессенджер',
'initial_admin_username' => 'myadmin',
'public_url' => 'https://chat.example.com',
```

Используйте уникальный случайный ключ установки. Например, команда `php -r "echo bin2hex(random_bytes(32));"` создаст ключ локально. `initial_admin_username` — логин будущего владельца: 3–32 строчные латинские буквы, цифры или подчёркивания. Если настройка отсутствует, используется `leosmleol`. После назначения владельца изменение этой настройки не передаёт права.

Оставьте `session_domain` пустым, если не требуется общая сессия между поддоменами. PHP должен иметь право записи в `data/` и `files/`; сохраните их `.htaccess`. Корневой `.htaccess` запрещает доступ к закрытым файлам. Убедитесь, что хостинг применяет правила Apache; иначе нужна отдельная настройка защиты. Не публикуйте конфиг и резервные копии базы.

## 3. Установка и владелец

1. Откройте `https://ваш-домен/install.php`, введите ключ установки в форму и создайте таблицы.
2. Зарегистрируйте именно тот логин, который указан в `initial_admin_username`. Регистрация в этот момент должна быть открыта. Войдите под этим пользователем и откройте `admin.php`. Владелец может добавлять других администраторов.
3. Удалите `install.php` с публичного сервера и очистите `install_key` в закрытом конфиге. Сохраните резервные копии конфига и базы отдельно.
4. При необходимости закройте регистрацию в админке и настройте звонки по [CALLS.md](CALLS.md).

Владелец может изменить название, регистрацию, лимит звонка, маршрут соединения и TURN в `admin.php`. Значения хранятся в базе и имеют приоритет над конфигом и `selfhost/settings.php`. Кнопка сброса удаляет изменения из базы. Секрет TURN хранится на сервере и не показывается после сохранения. Данные базы, сессии, `public_url`, STUN и первоначальный владелец меняются в `config.php`. Если там несколько TURN-адресов, форма покажет один; сохранение заменит список одним показанным адресом.

## Обновление и устранение ошибок

- Создайте копии базы, `config.php`, `data/` и `files/`; загрузите новый код, сохраняя эти данные. При необходимости обновления схемы следуйте описанию релиза. Проверьте вход и звонки.
- При ошибке базы проверьте её хост, порт, имя, логин, пароль, права и наличие `pdo_mysql`. Смотрите журнал PHP хостинга и не публикуйте пароли.
- Возврат на страницу входа может указывать на проблему хранения сессий, неверный домен cookie или переходы между HTTP и HTTPS. Используйте один HTTPS-адрес и проверьте журнал PHP.
- Браузер должен принимать cookie сессии. Для обновления интерфейса может понадобиться полная перезагрузка страницы или service worker.
- Для очистки временных данных звонков и ограничений запросов можно настроить ежечасный запуск `php /absolute/path/to/cleanup.php` в планировщике хостинга с той же версией PHP и расширениями.
