# Бесплатное доменное имя для LChat

Бесплатно проще получить **поддомен**, например `my-lchat.duckdns.org`: основной домен принадлежит сервису. Это постояннее временной ссылки, но условия и доступность могут меняться. DNS-имя само по себе не открывает порты, не запускает сайт и не выдаёт сертификат HTTPS.

## Вариант 1: Duck DNS и свой сервер

Подходит для VPS с публичным IPv4 или домашнего ПК с доступным публичным IPv4 и пробросом портов.

1. Откройте [Duck DNS](https://www.duckdns.org/), войдите одним из предложенных способов и в поле **sub domain** введите свободное имя, например `my-lchat`. Нажмите **add domain**. Результат: `my-lchat.duckdns.org`.
2. В поле **current ip** установите публичный IPv4 сервера и нажмите **update ip**. Для облачной VM укажите её публичный IP из панели провайдера, не локальный адрес `192.168...`. На домашнем ПК проверьте, что IP действительно публичный: при CGNAT простого проброса может быть недостаточно.
3. Если IP меняется, настройте обновление по инструкции [Duck DNS Install](https://www.duckdns.org/install.jsp) для своей ОС. Токен обновления храните в секрете. Для VPS со статическим IP автоматическое обновление обычно не нужно.
4. Откройте или пробросьте TCP 80 и 443 на машину с веб-сервером, включая правила облака и брандмауэр Windows. Если DNS указывает на сервер сайта, установите доверенный HTTPS-сертификат: например, настройте Caddy как обратный прокси на `127.0.0.1:8365`, указав свой домен. Caddy может автоматически выпустить и продлевать сертификат при доступных 80 и 443. Для Apache на Ubuntu см. [бесплатный хостинг](FREE_HOSTING_RU.md).
5. На Windows, после установки [Caddy](https://caddyserver.com/docs/install), в новом окне CMD запустите (подставьте своё имя):

   ```bat
   caddy reverse-proxy --from my-lchat.duckdns.org --to 127.0.0.1:8365
   ```

   Сайт должен уже работать на порту 8365. Оставьте Caddy запущенным, откройте `https://my-lchat.duckdns.org/` с другого устройства и проверьте сертификат. Настройте `public_url` LChat на этот HTTPS-адрес и проверяйте, что папки и база защищены. Если 80/443 заняты, DNS ещё не обновился или провайдер блокирует входящие подключения, автоматический выпуск может не пройти.

Команда `nslookup my-lchat.duckdns.org` помогает проверить DNS. **Для Playit:** DNS не хранит порт: A-запись на IP туннеля не превращает его нестандартный публичный порт в 443. TCP-туннеля к `IP:порт` недостаточно для обычного `https://имя/`; требуется шлюз с публичным 443 и корректным TLS, либо другой способ доступа. Для TURN нужны отдельные доступные порты и relay-диапазон: [инструкция по звонкам](CALLS_RU.md).

## Вариант 2: FreeDNS

На [FreeDNS](https://freedns.afraid.org/) зарегистрируйтесь, откройте **Subdomains → Add**, выберите доступный общий домен, свободное имя, тип `A` и публичный IPv4 своего сайта. Сохраните запись и настройте HTTPS и порты как выше. Сервис [предлагает бесплатные поддомены](https://freedns.afraid.org/signup/moreinfo/); доступность выбранного общего домена зависит от владельца, поэтому не используйте чужой поддомен как безусловно постоянный адрес.

## Вариант 3: временная HTTPS-ссылка без домена и открытия порта

Для проверки сайта на своём ПК можно использовать [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/). Установите `cloudflared`, запустите сайт на `127.0.0.1:8365` и выполните:

```bat
cloudflared tunnel --url http://127.0.0.1:8365
```

Откройте выданный `https://...trycloudflare.com` и оставьте процесс запущенным. Адрес меняется при каждом запуске; это тестовый туннель без гарантии доступности, не постоянный домен. Для LChat измените `public_url` на текущий адрес. Это туннель сайта, не TURN-сервер; храните учётные данные в безопасности и не используйте тестовый режим как постоянный публичный сервис.

Другие варианты: [программы для доступа извне](PORT_TOOLS_RU.md) и [установка на Windows](WINDOWS_HOST_RU.md).
